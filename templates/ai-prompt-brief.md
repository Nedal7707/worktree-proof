# Vibe-to-verified prompt brief

Use this brief when asking an assistant to turn a rough request into bounded WorktreeProof work.

Describe the desired user or operator outcome in one sentence. State the repository or artifact, runtime assumptions, data sensitivity, non-goals, and the evidence that will show success. Ask for independent lanes with unique relative scopes, a named integration target, focused checks, a preview or safe observation, a rollback or rescue route, owner confirmation boundaries, and a terminal closure receipt.

The assistant should begin with read-only inspection, use the least powerful available capability, and keep credentials, private paths, and sensitive payloads out of commands, fixtures, screenshots, logs, and receipts. It should stop before password, one-time code, passkey, billing, account-security, destructive live-data, or live-financial actions. A missing tool should produce a read-only result and an explicit limitation, not an invented success.

The response should end with the outcome, changed scopes, lanes and integration target, checks with pass or fail status, preview evidence, rollback or rescue evidence, known limits, and whether the lane is merged or deliberately abandoned.
