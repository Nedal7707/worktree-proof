# Governance

WorktreeProof is maintained as a lightweight, community-led project. The maintainers are responsible for release quality, security response, and keeping the documented behavior honest.

## Decisions

Prefer proposals backed by a reproducible example, a focused patch, tests, and documentation. Maintainers seek consensus in issues or pull requests; when consensus is not possible, the designated release maintainer makes a recorded decision and explains the trade-off.

## Maintainers

Maintainers may review, merge, revert, release, or pause work when it protects users or keeps the scope coherent. New maintainers are invited based on sustained, careful contributions and good judgment, not on volume alone.

## Releases

Version changes follow semantic-versioning intent where practical. A release should include passing checks, updated [CHANGELOG.md](CHANGELOG.md), and a short note about compatibility or migration needs.

## Changes to governance

Propose changes in a pull request. Preserve the project's unofficial community status, Apache-2.0 license, and security reporting expectations unless the community explicitly revisits them.
