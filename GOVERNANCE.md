# Governance

WorktreeProof is maintained as a lightweight, community-led project. The
maintainers are responsible for release quality, security response, and keeping
the documented behavior honest. This is not a foundation, company, or vendor
support program; see [SUPPORT.md](SUPPORT.md) for the public reporting path.

## Decisions

Prefer proposals backed by a reproducible example, a focused patch, tests, and
documentation. Maintainers seek consensus in issues or pull requests; when
consensus is not possible, the designated release maintainer makes a recorded
decision and explains the trade-off. A plan, benchmark draft, branch, or open
pull request is an intermediate artifact, not evidence that a change shipped.

## Maintainers

Maintainers may review, merge, revert, release, or pause work when it protects
users or keeps the scope coherent. New maintainers are invited based on
sustained, careful contributions and good judgment, not on volume alone. No
maintainer should request or publish secrets, private task context, or
unredacted production data.

## Releases

Version changes follow semantic-versioning intent where practical. A release
should include passing checks, updated [CHANGELOG.md](CHANGELOG.md), a short
note about compatibility or migration needs, and a redacted record of the
checks and release reference. A local benchmark may explain reproducibility,
but its timings are not a release-quality or adoption claim.

## Changes to governance

Propose changes in a pull request. Preserve the project's unofficial community status, Apache-2.0 license, and security reporting expectations unless the community explicitly revisits them.
